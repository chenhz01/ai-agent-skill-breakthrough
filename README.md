## 一句话定位

开源社区天天在「装 skill」，但**装了 ≠ 用了，用了 ≠ 超越**。本文给出一套可复用的四步闭环：
**学习它 → 超越它 → 突破它 → 再用起来**，并说明我们如何用它把一份 163 个 skill 的集合从「吃灰资产」变成「真实生产力」。

---

## 0. 为什么需要这套方法论

我们拿 `K-Dense-AI/scientific-agent-skills`（163 个科研/分析类 agent skill）做了真实实验，结论：

- 全量安装体积巨大、长期占用上下文窗口；
- 装完之后，**绝大多数 skill 从未真正被调用**；
- 通用型 skill 彼此是**孤岛**：无路由器、无组合协议、无跨 skill 证据溯源。

所以问题不是「skill 不够多」，而是「**没有把 skill 用起来的方法论**」。

## 1. 方法论总览（L1 公开层）

```
┌─────────────────────────────────────────────────────────────┐
│   学 Learn     并行深读全部 SKILL.md，提取能力 DNA + 触发条件   │
│      │                                                        │
│      ▼                                                        │
│   超 Surpass  交叉验证 → 定位「集体最大缺口」（通常是缺编排层） │
│      │                                                        │
│      ▼                                                        │
│   破 Break    构造超越性的「元层」：不是第 N+1 个孤岛，         │
│                而是把现有 skill 黏合、路由、溯源、可控云的枢纽  │
│      ▼                                                        │
│   用 Use      真实唤醒 ≥N 个 skill 跑一条端到端流水线           │
│                （不是装样子，是产生可验证产物）                 │
└─────────────────────────────────────────────────────────────┘
```

三条执行纪律：

1. **诚实核实**：先盘点真实库存与真实使用率，不轻信任何"已集成"摘要——装了≠用了；
2. **缺口优先**：超越的方式永远是补"集体最大缺口"（黏合层），而不是新增第 N+1 个孤岛；
3. **产物验收**：每一步必须产生可独立验证的产物链，宣称无证据 = 没发生。

## 2. 案例骨架：zhengming-skill-fabric 元编排层（L2 层）

用上述闭环对 163 个 skill 做了一轮完整升级，产出元编排层 `zhengming-skill-fabric`：

- **它解决什么**：把孤岛 skill 统一成"可路由、可组合、可溯源"的能力层；
- **它在闭环中的位置**：Step 2 定位的最大缺口（无编排）→ Step 3 的破局件 → Step 4 的真实唤醒验证；
- **结果**：从"一次性分析报告"变成"每天被真实任务复用的基础设施"。

完整攻击链记录（每轮 200 次多智能体对攻）、路由协议与分簇配置、内部拆分数据属于 **L3 配方层，合作交付**。
